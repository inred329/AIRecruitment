# 1. 報價說明

本報價依目前已知需求進行最粗略估算，目的在於提供 PoC 與 MVP 兩階段之預算參考。

目前已知流程包括：

- 求職者由 Meta 廣告進入 Messenger。
- 系統接收 Messenger 訊息並啟動招募對話。
- AI 協助蒐集求職者資料並進行初步職缺適配判斷。
- 對話與處理結果保存至人才庫。
- 符合條件者進入面試安排流程。
- 系統查詢可用時段並建立面試預約。
- 透過 Messenger、Email 或其他既定通知管道通知求職者與專員。

本報價尚未完成正式 Discovery、需求訪談、資料盤點、第三方平台權限確認與資安要求確認，因此屬概算，不視為最終固定總價。

# 2. PoC 階段

## 2.1 PoC 目標

以最低必要成本驗證以下核心流程是否可行：

1. Messenger 訊息能否穩定進入流程引擎。
2. AI 能否完成基本招募對話與資料整理。
3. 系統能否依明確條件產生初步篩選結果。
4. 符合條件者能否完成面試時段選擇與預約。
5. 對話、候選人資料與面試結果能否被保存及查詢。

## 2.2 PoC 暫定範圍

| 項次 | 工作項目 | 暫定內容 | 金額 |

| 1 | 需求確認與流程整理 | 需求訪談、核心流程、PoC 邊界、驗收條件 | NT$30,000 |
| 2 | Messenger 基本整合 | 單一粉絲專頁、Webhook、訊息接收與回覆 | NT$55,000 |
| 3 | AI 招募對話 | 固定問題流程、自由文字理解、基本 Prompt 與結構化輸出 | NT$70,000 |

| 5 | 基本人才能資料 | 候選人基本資料、對話紀錄、篩選結果 | NT$45,000 |

## 2.3 PoC 預估工期

約 8～10 週。

## 2.4 PoC 範圍限制

PoC 原則上採以下限制，以控制成本：

- 單一公司使用。
- 單一 Meta 粉絲專頁。
- 單一語言，以繁體中文為主。
- 支援 1～3 個測試職缺。
- 單一行事曆來源，例如 Google Calendar 或 Microsoft 365 擇一。
- 只提供基本管理頁面，不建置完整招募管理平台。
- AI 僅提供初步整理與建議，不直接做最終錄取或淘汰決策。
- 不包含多租戶、多公司、多品牌或多粉絲專頁。
- 不包含履歷 OCR、語音面試、影像分析、人格分析或模型訓練。
- 不包含正式高可用、災難復原、滲透測試及 24 小時維運。

# 3. MVP 階段

## 3.1 MVP 目標

在 PoC 驗證成功後，擴充為可供單一公司小規模正式營運的版本，補足必要的管理、權限、異常處理與操作流程。

## 3.2 MVP 暫定範圍

MVP 包含 PoC 全部成果，並增加以下內容：

- 多職缺管理。
- 候選人狀態管理。
- 人工覆核與人工接手機制。
- 基本角色與權限。
- 較完整的面試改期、取消與提醒。
- 基本個資告知與同意紀錄。
- 操作、對話、篩選及預約歷程保存。
- 外部服務失敗紀錄與重新執行。
- 基本統計與管理查詢。
- 正式部署、備份與基本監控。
- 使用者驗收測試與教育訓練。

# 4. 低價成立條件

本報價已採壓低成本方式估算，成立條件如下：

- 由單一開發團隊承作，避免多層轉包。
- 優先採用既有框架、AI API、n8n 或等效流程工具。
- 採單體式架構與單一資料庫，不建置微服務或 Kubernetes。
- 管理後台以實用為主，不進行高度客製化視覺設計。
- 第一階段不建置多租戶 SaaS。
- 第一階段不提供複雜報表與商業智慧功能。
- 客戶需提供 Meta、Email、行事曆、網域及雲端帳號。
- 客戶需指定單一窗口快速確認需求。
- 正式開發前需完成最基本需求確認及範圍凍結。

# 5. 不含項目

以下項目不包含於上述固定開發費：

- Claude、OpenAI 或其他 AI API 使用費。
- Make、n8n Cloud 或其他自動化平台訂閱費。
- Meta、LINE、Email、Google Workspace 或 Microsoft 365 相關費用。
- 雲端主機、資料庫、備份、儲存空間、網域及 SSL 費用。
- Meta App Review、商業驗證或第三方平台政策變更造成之額外工作。
- 既有 ATS、CRM、ERP 或人事系統之客製介接。
- 履歷 PDF、Word、圖片 OCR 與欄位辨識。
- 多語言、多公司、多租戶、多粉絲專頁。
- 語音或視訊面試、自動逐字稿、情緒與人格分析。
- 客製 AI 模型訓練、微調或準確率保證。
- 正式滲透測試、高可用、災難復原及 24 小時 SLA。
- 法律、個資、資安或人力資源制度顧問服務。
